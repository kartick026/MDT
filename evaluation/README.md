# Accuracy evaluation protocol

`development.json` contains 20 assistant-authored source-pair controls. They verify regressions only. `holdout.template.json` is intentionally empty and cannot pass the evaluator. No independent labels have been manufactured.

1. Independent reviewers select at least ten repositories not in `tuning-repositories.json`. That exclusion list includes the ten earlier replay repositories and FastAPI itself, which was also used for diagnostic fixes. Forks or duplicate examples do not create independence.
2. Pin repository and before/after commit SHAs, file paths and source-content provenance. Sample real positive and negative changes, including mundane edits, large files, parser failures and missing evidence. Group by repository, framework and language so one project cannot dominate the claimed coverage.
3. Two people label each candidate without seeing MDT predictions. Resolve disagreements; record their names/roles and adjudication notes in the private review record. Use true/false only for determinate held-out cases; keep ambiguous cases in a separately reported abstention challenge set. Do not silently delete hard cases from the inventory.
4. Complete the holdout template: `provenance.independent`, `adjudicated`, `reviewers`, `used_for_tuning:false`, `frozen_at` and `repository_revisions` (owner/repo → full 40-character revision). Freeze and hash the dataset before invoking the detector. Obtain reviewer sign-off on the immutable hash.
5. Each case requires a unique `id`, `repository` matching the manifest, a supported `family`, Boolean `expected`, and `changes` with `file_path`, `old_content`, `new_content`. For contextual models, include `source_context: {before: {path: content}, after: {path: content}}`. Keep commit IDs and review rationale as extra provenance fields. JSON is data: no repository commands or imports are executed.
6. Run `python scripts/evaluate_accuracy.py --dataset evaluation/holdout.json --output scratch/readiness/accuracy-holdout.json`. Preserve failures and the complete case report. The program invokes the actual parser and deterministic finding predicates; it does not invent scores or invoke an LLM.
7. Review precision/recall by family and by repository. The emitted Wilson intervals describe individual case counts; correlated changes from the same repository mean these intervals can overstate population confidence. A separate repository-level statistical review is needed before broad accuracy claims. Also measure graph nodes/edges and smell findings separately before extending the advertised scope.
8. If any case informs a detector change, retire that corpus to development data and prepare a new independent holdout. Do not tune thresholds on the holdout. Tie final evidence to the source fingerprint and dataset digest.

Recall includes abstained positives as missed findings. Precision excludes abstentions, so prediction coverage is a separate required gate. A family with no predicted positives or no positive labels has an undefined metric, not 100%. Minimum sample sizes and every family are checked independently. `null` expected labels in development controls deliberately test abstention; they are not credited as labeled classification examples.

Numeric risk/debt scores remain heuristic indicators. Accuracy of a binary finding does not calibrate the probability of an outage or justify auto-approving a deployment.
