# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers reviewing microservice dependencies, architectural findings, and possible changes. The user confirmed that the complete existing workflow must remain available with simpler navigation.

## Product Purpose

MDT (Microservice Drift Tracker) provides evidence-based architecture review. Users choose or import a repository, review analysis results, inspect dependency graphs and findings, compare captured topology, and review saved history.

## Capabilities and Constraints

- Preserve existing project, authentication, analysis, graph, findings, remediation-preview, drift, history, policy, export, and diagnostic functionality.
- The public demo is a recorded illustrative example, not live observations.
- Remediation previews model changes on copied graphs; they do not modify source or prove runtime reliability. Preserve the distinction between improved, unchanged, and worse outcomes.
- Keep the React/Vite frontend and current backend API contracts.
- Local implementation and validation do not establish deployment or publication.

## Brand Commitments

Keep the MDT name and academic-alpha disclosure. The user requested an easy-to-use neumorphic frontend.

## Evidence on Hand

Existing components in frontend/src, bundled recorded demo data, source-backed analysis and graph views. Do not invent customer claims or performance metrics.

## Product Principles

- Give users a clear next action without removing advanced evidence.
- Distinguish observed, captured, illustrative, and modeled information.
- Preserve working routes and saved links.
- Make controls readable, keyboard accessible, and usable on small screens.
